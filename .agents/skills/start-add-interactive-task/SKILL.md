# Добавить интерактивную табличную задачу

Все пути к коду и конфигу ниже указаны относительно корня репозитория `start`.
Перед изменением сверяйте контракт с текущим кодом SDK.

Для задачи в разделе «Команды» создайте один модуль `cli/commands/<имя>.py`
и запись `[[commands.tasks]]` в `config.toml`.
SDK находится в пакете `cli/command_sdk`, библиотека команд — в `cli/commands`.
SDK не импортирует конкретные команды; менеджер загружает их по ссылкам из конфига.

- [command_sdk](../../../cli/command_sdk/__init__.py) — публичный контракт: `TaskContext`,
  `TableSnapshot`, тип `Provider` и загрузчик `load_provider`. Не зависит от Textual.
- [screen.py](../../../cli/command_sdk/screen.py) — общий экран: фильтры, таймер,
  вывод ошибок и выход. Конкретные команды его не импортируют и не меняют.
- [listening_ports.py](../../../cli/commands/listening_ports.py) и
  [network_processes.py](../../../cli/commands/network_processes.py) — готовые примеры.

В файле команды держите её аргументы, разбор вывода и точку входа
`async snapshot(context, filters)`. Импортируйте типы из `cli.command_sdk`.
Регистрацию платформ, категорию и поля фильтров задавайте в `config.toml`.

## 1. Добавьте provider

Функция принимает `TaskContext` и `dict[str, str]` фильтров, возвращает
`TableSnapshot(columns=tuple[str, ...], rows=list[tuple[str, ...]])`.
Количество значений каждой строки должно совпадать с количеством колонок.
Для пустого результата верните те же колонки и `rows=[]`.

Например, в новом `cli/commands/processes.py`:

```python
from cli.command_sdk import TableSnapshot, TaskContext


async def snapshot(
    context: TaskContext, filters: dict[str, str]
) -> TableSnapshot:
    output = await context.run("ps", "-e", "-o", "pid=,comm=")
    query = filters.get("command", "").casefold()
    rows: list[tuple[str, ...]] = []
    for line in output.splitlines():
        pid, command = line.strip().split(maxsplit=1)
        if query in command.casefold():
            rows.append((pid, command))
    return TableSnapshot(columns=("PID", "COMMAND"), rows=rows)
```

Используйте `await context.run(*argv)` для внешних команд. Каждый аргумент передаётся
отдельно, без shell: пайпы, перенаправления и подстановки не интерпретируются.
Команда получает корень репозитория как `cwd`, переменную `REPO`, `LC_ALL=C` и
закрытый stdin. Возвращается декодированный stdout.

Для ожидаемых ненулевых exit codes задайте `allowed_codes`, например `(0, 1)`.
Ненулевой код со stderr всё равно считается ошибкой. Остальные ошибки передаются
в экран с traceback и диагностикой процесса; не заменяйте их пустым снимком.

Таймаут одного запуска — `context.timeout`, по умолчанию 15 секунд. Если команде
нужен другой предел, задайте его в provider. При отмене или таймауте SDK завершает
процесс и ожидает его выхода; на POSIX обрабатывает также группу процессов.
Не запускайте отдельный фоновый цикл и не подавляйте `CancelledError`.

## 2. Зарегистрируйте задачу и фильтры

```toml
[[commands.tasks]]
name = "processes"
title = "Процессы"
category = "Система"
description = "Обновляемая таблица процессов с поиском по команде."
refresh = 2
sudo = false
[commands.tasks.view]
darwin = "cli.commands.processes:snapshot"
linux = "cli.commands.processes:snapshot"
[[commands.tasks.filters]]
name = "command"
label = "Команда содержит"
default = ""
```

Указывайте `view` как `module:function` для каждой поддержанной `sys.platform`
(`darwin`, `linux`, `win32`). Без варианта для текущей ОС задача недоступна.
`run` и `view` могут сосуществовать для разных ОС, но не для одной.

`category` объединяет задачи под заголовком в таблице менеджера. Без значения
используется «Общее». Порядок групп и задач определяется порядком в конфиге;
недоступные на текущей ОС задачи показываются отдельно внизу.

Задайте `refresh` в секундах: допустимо от `0.2` до `3600`, по умолчанию `2`.
Первый снимок запрашивается при открытии; таймер пропускает обновление, пока
предыдущее выполняется. Изменение фильтра и `Ctrl+R` запускают новый запрос,
отменяя предыдущий. Устаревший результат не заменяет актуальную таблицу.

Назовите фильтры уникально по шаблону `[a-z][a-z0-9_-]*`. Без `options` поле будет
`Input`; с непустым списком строк `options` — `Select`. Например,
`options = ["tcp", "udp", "all"]` требует `default = "tcp"` либо другое значение
из этого списка. По умолчанию `default = ""`, `label` совпадает с `name`.
Все значения поступают provider как строки; смысл пустого значения и проверку
диапазонов реализуйте в provider. Изменённый текст `Input` передаётся без пробелов
по краям.

Для привилегированной задачи установите `sudo = true`. При её открытии менеджер
один раз выполняет `sudo -v` в обычном терминале перед показом таблицы. При отказе
таблица не открывается. Затем `context.run` обновляет timestamp через `sudo -n -v`
и выполняет команду через `sudo -n --`: пароль внутри таблицы не запрашивается.
Не добавляйте `sudo` в argv provider. У shell-задач `run` поле `sudo` служит только
пометкой — там команда сама определяет использование `sudo`.

## 3. Проверьте снимки и управление

Проверяйте provider на фиксированном выводе команды через подмену
`TaskContext.run` на `AsyncMock`. Сравнивайте снимок и переданный argv: пустой
результат, корректные фильтры, ошибочный ввод и ошибки команды. Эти тесты не должны
вызывать реальные системные команды или `sudo`. Для тестов экрана используйте
тестовый async provider и задачу с `sudo=False`.

При ручной проверке откройте задачу из раздела «Команды» и проверьте:

- `Tab` переводит фокус между таблицей и фильтрами.
- `Enter` из текстового `Input` возвращает фокус в таблицу.
- `q` возвращает в менеджер из таблицы; в `Input` это обычный символ.
- `Esc` возвращает в менеджер из любого поля, отменяя текущий запрос.
- `Ctrl+R` запрашивает новый снимок; фильтры применяются при изменении значения.

Для проверки существующих providers учитывайте их собственную семантику.
`tcp-listen` показывает TCP в состоянии `LISTEN` и UDP-сокеты, принимает пустой
порт либо число `1–65535`; `protocol` — `tcp`, `udp` или `all`.
`nettop` доступен на macOS: `application` передаётся в `nettop -p` как точное имя
процесса или PID, без поиска по подстроке; пустое значение убирает ограничение.
По умолчанию показаны все приложения, протокол — `tcp`.

Таблица `nettop` периодически получает отдельный CSV-снимок через `nettop -L 1`,
а не встраивает его нативный curses-интерфейс. Колонки `IN`/`OUT` показывают
накопленные `bytes_in`/`bytes_out` из снимка: provider не вычисляет разницу между
снимками или скорость в байтах в секунду. Для нативного интерактивного интерфейса
утилиты используйте отдельную shell-задачу `run`.

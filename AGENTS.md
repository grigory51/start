# Repository Guidelines

## Структура проекта

`start` управляет персональным окружением: Claude Code, Codex, dotfiles и служебными командами.

Это личный проект для одного владельца. Не вводи командные процессы без необходимости.

- `cli/` — Python CLI и Textual TUI; `cli/ai/` — адаптеры клиентов, `cli/commands/` — интерактивные задачи, `cli/command_sdk/` — их SDK.
- `tests/` — тесты конфигурации, адаптеров, provisioning и интерфейса.
- `ai/` — исходники агентов, инструкций, правил, skills и hooks.
- `dotfiles/` — настройки приложений, включая профили OrcaSlicer; `scripts/` — обёртка запуска и служебные скрипты.
- `contrib/` — внешние git submodules. `config.toml` задаёт общий каталог, `config.local.toml` хранит локальные переопределения.

## Команды разработки

Нужен Python 3.11+. Предпочитай `uv`; обёртка `scripts/run.sh` поддерживает запуск без него через `.venv`.

- `uv run start --help` — справка CLI.
- `make manage` — открыть TUI.
- `make up -- --dry-run` — посмотреть план синхронизации; проверки зависимостей при этом выполняются.
- `make up` — синхронизировать AI и Files в пользовательское окружение.
- `make ai:codex` / `make ai:claude` — синхронизировать отдельный клиент.
- `uv run python -m unittest discover -s tests` — выполнить тесты.

## Стиль и именование

В Python используй четыре пробела, `snake_case` для функций и модулей, `PascalCase` для классов, явные аннотации типов и `from __future__ import annotations`. Сохраняй стиль соседнего кода. Отдельные formatter и linter в `pyproject.toml` не настроены.

Группируй связанные настройки по сущностям. Переиспользуй существующие модели и адаптеры вместо параллельных механизмов. Комментарии должны объяснять причины нейтральным техническим языком.

## Тестирование

Используется `unittest`: файлы `test_*.py`, методы `test_*`. Для изменений логики добавляй проверки поведения, ошибок и совместимости. Применяй временные каталоги и mocks, чтобы не изменять реальные настройки пользователя. Числовой порог coverage не задан. Отдельный файл запускается так: `uv run python -m unittest discover -s tests -p 'test_config.py'`.

## Коммиты и PR

По умолчанию работай в текущей ветке. Создавай новую ветку или worktree только по явной просьбе владельца. История содержит короткие предметные сообщения и сообщения вида `docs(cad): ...`; обязательного формата нет. Если запрошен PR, объясняй проблему и итоговое поведение, связывай issue при наличии. Для изменений UI прикладывай снимки, если они помогают оценке. Не дублируй результаты CI; указывай существенные ограничения проверки.

## Конфигурация и работа агентов

Не коммить секреты, локальные настройки и generated runtime-файлы. Глобальные инструкции правь в `ai/instructions/global.md`, принципы — в `ai/rules/my-principles.md`, а не в установленных копиях. Следуй этим инструкциям и соответствующим `ai/skills/my-principles/tech/`.

Отвечай по-русски. Без разрешения владельца не запускай приложение, provisioning или проверки. Commit, merge и push выполняй только по явной просьбе.
